# ADR-0001 · AI 框架采用方式：双轨制（确定性核心 / Agent 域 / MCP 对外）

- **状态**：已接受（2026-10-22 用户确认，见实施规划 §1；本文件为落仓全文）
- **关联**：清单 FN-0-09（AI 治理边界）、FN-8-08（双模式）、FN-A-04（MCP Server）；蓝图 §10、§1.6；实施规划 §1/§2

## 背景

平台同时需要两类性质完全不同的能力：

1. **确定性能力**：税额/容差计算、查重、状态机流转、授权与红线检查、受控写、审计哈希链——必须可测试、可回归、可审计，不允许任何概率性；
2. **不确定性能力**：对话意图理解、差异解释、主动调查线索、字段映射推荐、异常归因——适合 LLM/Agent，但只能"建议"，不能"执行"。

若把 LLM 织入核心（单体 + AI 插件式），会同时污染可测试性（确定性断言被模型输出动摇）、可交付性（离线/私有化客户不接 LLM 也要能用菜单模式完成全部复核，蓝图 §1.6）、可替换性（模型/框架换代牵动内核）。

## 备选项

| 方案 | 说明 | 否决理由 |
|---|---|---|
| A. 单体 + LLM 插件 | FastAPI 内直接调用模型 | 违反 FN-0-09"LLM 输出永不直接写入 checks/status/字段值"；核心被 AI 可用性绑架 |
| B. 独立 AI 微服务（通用 HTTP） | LLM 域自成一服务，随意互调 | 边界靠约定不靠结构，agent 可能绕过受控写框架直接落库；依赖纪律不可评审 |
| C. **双轨制（选定）** | `backend/` 确定性核心（零 LLM 依赖）；`agent/` LangGraph 域**只作为 backend API 消费者**；`mcp/` MCP Server 承载对外 Agent 生态（SAP Joule/第三方），6 工具=4 只读+2 受控写（confirm_token） | — |

## 决策

采用双轨制三段结构：

- `backend/`：Python + FastAPI，实现规则引擎/状态机/审计链/受控写命令框架；**不得 import agent，不得出现任何 LLM 调用**；
- `agent/`：LangGraph 域（对话、主动调查、差异解释、映射推荐、归因），**只能调用 backend 内部 API**（与 MCP 工具同源，工具同源原则 FN-8-08/FN-2 层纪律）；
- `mcp/`：MCP Server 对外封装同一套受控接口；写工具必须携带人工确认 token，AI 禁止静默写。

## 后果

- **正面**：LangGraph/模型可整体替换而不动核心；确定性功能不受 LLM 可用性影响；依赖纪律可机械校验（import 检查列入代码评审红线）；对外生态与内部 Agent 走同一受控面，无私有旁路。
- **代价**：API 契约先行压力（M0 必须先冻结 contracts/）；agent 域功能开发需等 backend API 就绪（里程碑已按 M1→M5 排序消化）。
- **约束落点**：实施规划 §2 依赖纪律 1/2/5 条；CLAUDE.md §4；M5 验收项④（写工具无 confirm_token 被拒）。
